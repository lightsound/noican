# Result record — 1-channel driver (0.2.0), 2026-09-11

Hardware run for PR #32 (branch head `7cc0dfd`), which builds the Noican
driver with one channel, the UID base `com.lightsound.noican.mic` and
version `0.2.0`. The app build is the same as `main` (`8635283`, PR #33,
Developer ID with the audio-input entitlement) plus the PR's
documentation and test changes; no runtime code differs. It scores the
"Acceptance checklist (1-channel driver)" of
[docs/macos-hardware-test.md](../macos-hardware-test.md) and the Driver
check steps that a swap exercises. The run was operator-driven (device
selection, On/Off, Preview, model switch, slider) with recording and
measurement scripted by the agent on the same Mac.

## Observations

- `Output underruns: 2 (model: passthrough)` was logged once, at the
  first split-transport start on the FreeClip (13:58:21, the line is
  emitted with the startup diagnostics). The second FreeClip start
  (13:59:34) logged none, and no aggregate-path start logged any. The
  split transport's callback is unchanged by PR #32 and the counter
  reads at start-up; not treated as a regression, recorded for the
  underrun history.
- Re-selection: QuickTime kept the Noican device selected across the
  UID change. Whether it matches by name or falls back to the same
  default input is not known; meeting applications may behave
  differently (docs/driver.md, "History").
- The first two attempts at the built-in take captured almost nothing
  because the operator and the agent were not synchronized on when to
  speak (the takes were discarded, not measured against anything). The
  paired raw+Noican recording driven by the operator from a terminal
  removed that problem and is the method recorded above.
- A `log stream` left running in the background did not survive
  between sessions (as on 2026-09-09); `log show --start …` recovered
  everything needed.
- The Developer ID app build captured the microphone without any
  `tccd` denial, as PR #33 intended.
